# テスト項目

このツールで確かめている項目の一覧です。計算は `tests/lens.test.js`、画面は `tests/ui/` で自動で確かめます。自動にできないものは「手で確かめる項目」に残します。VCA の読み込みと書き出しが規格(DCS v3.14)の決まりを守るかのテスト(`tests/conformance.test.js`)は、決まりごとに [conformance.md](conformance.md) にまとめています。

## 動かし方

```
npm test
node tools/trace.js --check
npm run mutate
```

- `npm test` は計算のテストと規格のテストを動かします。`tools/trace.js --check` は、[conformance.md](conformance.md) の「テスト」の決まりにテストがあるか、[conformance-tests.md](conformance-tests.md) が古くないかを確かめます(作り直すときは `npm run trace`)。`npm run mutate` は、`tools/mutate.js` の一覧のとおりに実装をわざと壊し、そのたびにテストが失敗するか(壊れたことを見つけるか)を確かめます。

```
node tests/ui/cdp.js index.html tests/ui/steps.js
```

- リポジトリのフォルダで実行します。3 つ目に画像を置くフォルダを指定できます(省くと OS の一時フォルダの `vca-ui-check`)。
- 画面の検査は、Chrome をヘッドレスで起動して操作します(Node.js 22 以上。`fetch` と `WebSocket` を使う)。Chrome は決まった場所から探し、見つからないときは環境変数 `CHROME` で場所を指定します。
- 3D の表示用の three.js を CDN から読むので、インターネット接続が必要です。
- 各項目の結果が `OK` / `NG` で出て、最後にコンソールのエラー・例外があれば `PROBLEMS` に並びます。画面の画像は指定したフォルダに保存されます。

## 1. 計算(`tests/lens.test.js`、19 件)

| 項目 | 確かめること |
|---|---|
| 球面のマイナスレンズ | 縁厚が厚いレンズの式と一致する |
| プラスレンズ | 最も薄い縁が最小縁厚になるように中心厚を決める |
| 乱視 | 乱視軸 0° のマイナス乱視は上下の縁が厚い |
| 偏心 | 右眼の光学中心が鼻側にあると、マイナスレンズは耳側が厚い |
| プリズム | 基底の向きの縁が厚くなる。成分表示と 360° 表示を相互に直せる |
| メッシュ | 閉じていて、外向きで、体積が正しい |
| VCA の読み込み | サンプルから両眼の玉形を読める。Z データ(ZFMT)・穴あけ(DRILLE)を読める |
| 許容差 | JIS T 7337(ISO 21987)の表の値になる |
| ヤゲンの位置 | DCS の BEVP の決め方に従う |
| 縁の面の傾き | 光学中心が玉形中心なら縁の面は光軸に垂直。下げると「ずらした量 ÷ カーブの半径」ほど傾き、上げると逆向きに同じだけ傾く(`Lens.edgePlane`)。縁の面を立てる回転(`m.toFrame`)は長さを保ち、光学中心を大きくずらしても三面図に NaN が出ない |
| 三面図 | A3 横・推奨尺度で、数値に NaN が無い。DXF(R12)にできる |
| 資料との照合 | K 値の表、乱視・偏心の計算例、メーカーのブランクの公表値と合う(詳しくは `docs/validation.md`) |

## 3. ほかのツールとつないだ流れ(`tests/flow.test.js`・`tests/ui/flow.js`)

隣に vca-shape-maker・vca-ptn-converter があるときだけ動きます(無ければ飛ばします。GitHub Actions は 3 つとも取ってくる)。

```
node --test tests/flow.test.js
npm run ui:flow
```

| 流れ | 確かめること |
|---|---|
| shape-maker → このツール | 角の丸い形・角のとがった五角形 × 写した眼(右・左)× 点の数(360・1440)× 穴(無し・丸穴と長穴)の 16 通りで、両眼の半径が 1° ごとに shape-maker の書いた値と 0.02 mm 以内、HBOX・VBOX、穴の位置(反対の眼は x が反対)、JOB |
| shape-maker → ptn-converter → このツール | 同じ 16 通りを、ptn-converter で VCA(PTN・JOB は同じ中身)に書き直して(元のレコードを引き継ぐ・引き継がない)、また DXF にして読み込み直してから VCA にして読む |
| このツールの厚みの VCA | vca-parser.js で警告が無く、ファイルの決まり(REQ・JOB)を守る。玉形が無いことを ptn-converter とこのツールが知らせる。玉形のファイルに足すと、どちらでも読めて中心厚が入る |
| このツールの三面図の DXF | ptn-converter で DXF と判定し、閉じた輪郭を読める(縁の加工 4 通り) |
| このツールの STL | 縁の加工 4 通り・両眼で、三角形の数・大きさ・法線(長さ 1、向き)・頂点が網と同じで、体積が網と同じ。面積が 0 の三角形は書かない |
| 画面をつないだ流れ | shape-maker の画面で形と穴を作り JOB=FLOW1 にする → その VCA をファイルとして ptn-converter の画面に読み込み、作り直した VCA の JOB・DRILLE・保存名を確かめる → その中身を .vca・.oma・.ptn・.job の名前でこのツールの画面に読み込み、両眼・玉形幅・穴・厚みの VCA の JOB を確かめる |

## 4. 手で確かめる項目

自動の検査では見られない、または見た目の判断が要るものです。

- 3D の見え方: 空色の背景の上で、レンズ・リム・厚みの色分けが見やすいか(ライト・ダーク)
- リムの形: ヤゲンの山がリムの溝に収まって見えるか(ヤゲン確認・周の断面)
- ドラッグでの回転・移動・拡大、「レンズを回す」でのドラッグ
- ファイルを置く(ドラッグ)での読み込み。選んだときと同じ読み込みは `tests/ui/flow.js` が .vca・.oma・.ptn・.job で確かめる
- 印刷(A3)のプレビューで、図面が 1 枚に収まるか。印刷は新しいウィンドウを開くので、自動の操作ではブラウザに止められて確かめられない
- 保存したファイルを他のソフトで開けるか(STL は 3D ビューアー、DXF は CAD)

## 5. 仕様として残しているもの

確かめた結果、不具合ではなく決めたとおりの動きのものです。

- 読み込んだファイルに無い値(縁の加工・処方など)は、前の入力のまま残る。サンプルを切り替えたときも同じ。
- 右眼だけ(または左眼だけ)のファイルは、反対の眼を左右反転して両眼として扱う。
- 3D と三面図(平面図・側面図・断面)はフレーム基準(縁の面を立てる)で描く。正面図は縁の面に投影したもので、玉形の座標のまま。
- 回したレンズの向きは、視点を変えても戻らない。「傾きを戻す」で戻す(装用状態の傾きは戻さない)。
